# 链死符号补前置：官方机制是 CONFIG_XNU_EXTRA_LD_ARCHIVES（build-xnu-4k-baseline.sh:812 把它
# 追加到 KERNEL_EXTRA_ARCHIVES 尾部，普通归档路径，不是 force_load，所以只按未定义符号惰性拉取）。
# 提供器是 alioth 的同款官方文件 package/LinkStubs.c + package/BootProgressStubs.c（原样拷进本仓），
# 由 scripts/build-link-stubs.py 编成 build/link-stubs/libLinkStubs.a。
# 原因：libBootProgress.a 引用 sheng 专属组件（GOP 显示 / Novatek 触摸 / cpufreq / RAM 盘 / HID）的
# 计数器，我们用不到的这些组件没链，静态内核链又不放过 weak_import 未定义符号（alioth 也这样写：
# configs/alioth_defconfig:87-90）。桩都是 weak 零值：读到 0 就是「该组件没做过任何事」，
# 以后真链上某个组件时，真定义自动赢过桩。
# HID 输入层（官方 ShengHidInput）：libDbyHidInput.a 必须 **-Wl,-force_load**，不能只写路径。
# 原因：package/LinkStubs.c 已经用 weak 空定义满足了 native_hid_input_probe，普通归档按未定义符号
# 惰性拉取时，那个 weak 桩正好把唯一的未定义符号满足掉，整个归档一个条目都不会被拉进来 —— 结果是
# 「编得出、链得过、屏幕上什么都不发生」。官方 build-xnu-4k-baseline.sh:576-755 对每个组件归档用的
# 就是 -Wl,-force_load,<path>；EXTRA_LD_ARCHIVES 在 :755 被原样追加进 KERNEL_EXTRA_ARCHIVES，再由
# MakeInc.kernel 拼进 $(LD) 命令行，所以空格分隔的 -Wl,-force_load,<路径> 是合法形式。
# 归档来源：scripts/build-dby-hid-input.py（见 work/tracks/hid/，10 个自有槽位 + handleReport
# @0xfffffff004add0c4 已按 prelink 审计），产物按本仓既有惯例「自备进构建树」放在
# {tree}/build/dby-hid-input/libDbyHidInput.a。它需要的 native_touch_seq/count/xs/ys/ids 由
# package/DbyTouch/DbyTouch.cpp 提供（强定义），native_legacy_transfer_calls 由 LegacyDisplayProbe.cpp
# 提供；归档内的 DbyHidSinkStubs.o 只有 weak 桩，真定义自动赢过它，不需要改桩。
# 回退 = 删掉本行末尾的 -Wl,-force_load,{tree}/build/dby-hid-input/libDbyHidInput.a 这一个词。
CONFIG_XNU_EXTRA_LD_ARCHIVES="{tree}/build/link-stubs/libLinkStubs.a {tree}/build/dby-touch/libDbyTouch.a -Wl,-force_load,{tree}/build/dby-hid-input/libDbyHidInput.a -Wl,-force_load,{tree}/build/cpufreq/libCpuFreqProbe.a -Wl,-force_load,{tree}/build/gpusmmu/libDbyGpuSmmuProbe.a"
CONFIG_XNU_CRYPTO_BOOTSTRAP="prelinked"
