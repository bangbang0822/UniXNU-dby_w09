# 整合说明：把 DBY-W09 触控子系统装到另一块板子上

> 这份文档假设你要在**自己的** XNU/UniXNU 移植里使用本包的触摸驱动。
> 读完再动手；第 2 节和第 6 节是"照着做会炸"的部分。

---

## 1. 先判断：这个包适不适合你

只有同时满足下面三条，才值得继续：

1. 触摸 IC 是 **Novatek N9Z / NT36523 系**，且工程号与 W2599Z1100 兼容（固件只对这一颗验证过）；
2. 触摸挂在 **GENI SPI** 上（QUPv3 SE），且你能拿到 `SE 基址 / IRQ / CS / 复位` 四个 GPIO 号；
3. 你能接受**每次开机上传 0x30000 字节固件**（本驱动这么做，因为 vendor 分区里的固件不保证已在 IC 内）。

不满足 1 或 2 的话，正确的做法是拿本包当**结构参考**（阶段阶梯、行 42 诊断、HID 发布契约），
而不是直接编译。

---

## 2. 绝对不要照抄的东西（花屏的根源）

包里 `02-配置片段/board.toml-kernel-args-全文.txt` 是**本板 46 条完整命令行**，其中：

- **只有 4 条可以移植**：`dby-touch`、`dby-touch-se`、`sheng-touch-hid`、`dk`；
- 其余 42 条属于本板的显示（13 条）、存储（9 条）、OS/UI 与其它（18 条）、复位与日志（2 条）策略。

**最像花屏的一条**：`offline-legacy-retire=1` 与 `-cpu-present=1` **都缺**时，屏幕**只出第一帧**
然后定格，而内核诊断页还在往上画——看起来就是花屏。

三条"硬耦合"（少一条不是显示错，而是 panic / 黑屏 / 冻结首帧）：

| 参数 | 缺了会怎样 | 代码位置 |
| --- | --- | --- |
| `offline-legacy-register=1` | **panic** | `NativeLegacyDisplay.cpp:316-318` |
| `offline-legacy-pm=1` + `phase=4` | `pm` **设了但不是 1**、或 `phase≠4` → 启动失败/黑屏；**完全不写 `pm` 是安全的** | `NativeLegacyDisplay.cpp:287-306` + `LegacyDisplayProbe.cpp:471`（phase 解析） |
| `offline-legacy-retire=1` 或 `cpu-present=1` | 都缺 → 只出第一帧 | `:359-360`、`:520-530` |

另外**绝对不要开** `sheng-dpu-scanout>=2`：那条路径把 `kVig`/`kCtlFlush`/`kBootIova`/
**`kBootStride=0x2fa0`**（12256 字节，不是 1600×4）全部硬编码；本板之所以安全，只因
`LinkStubs.c:54-64` 的弱桩 `native_ufs_dpu_map` 返回 0 让它自己退场。

## 3. 移植步骤

### 第 0 步：改板级常量（`DbyTouchBoard.h`）

必须逐条核对的字段：

| 常量 | 本板值 | 你要填 |
| --- | --- | --- |
| `DBY_TOUCH_SE_BASE` | `0x00880000` | 你的 SPI SE 基址 |
| `DBY_TOUCH_SE_IRQ` | 373 | 你的 SPI 中断号（`DBY_TOUCH_IRQ` 这个常量不存在） |
| `DBY_TOUCH_GPIO_CS` / `DBY_TOUCH_GPIO_RESET` / `DBY_TOUCH_GPIO_IRQ` | 43 / 98 / 39 | 你的引脚（三个名字都带 `DBY_TOUCH_GPIO_` 前缀） |
| `DBY_TOUCH_MATRIX_ROWS` / `_COLS` | 50 / 32 | 你的矩阵（**在 `DbyTouch.cpp:314-315`，不在头文件**） |
| `DBY_TOUCH_PANEL_W` / `_H` | 1600 / 2560 | 你的面板 |
| `DBY_TOUCH_HID_LONG_AXIS` / `SHORT_AXIS` | 30480 / 20320 | 与消费者一致（名字是 LONG/SHORT） |
| `DBY_TOUCH_TILE(...)` | 枚举 6 个引脚 | 你的引脚表（**未列出的脚必须返回 `TILE_NONE`**） |

改完先编译，不要刷。

### 真实阶段阶梯（**按代码，不按常量名**，2026-11-04 审查更正）

驱动里定义了 `OFF/CENSUS/CLOCKS/IDENTIFY/FRAMES/PUBLISH/ENABLE/HOSTCMD/FWUPLOAD` 九个常量，但**实际只比较
其中四个阈值**：`0`、`≥2`、`≥6`、`≥7`、`≥8`。`dby-touch=3/4/5` 与 `=2` **行为相同**——但前提是：
`dby-touch-se=1` 且 `gClkOk`/`gSeRcgOk` 成立、SE verdict 为 FIFO-usable（`DbyTouch.cpp:3894-3897, 3938`），
并且 SPI 环回通过（`rc==0 && loop==0xA55AC33C`，`:1845`）；否则链在 2→3 那一跳就停了。
`stage2Thread` 会依次启动 `stage3Thread`（SPI 初始化 + 环回）、`stage4Thread`（SPI 引脚复用 + 身份）、
`stage5Thread`（8208 字节帧读 + 发布）。

| 取值 | 实际行为 | 出问题说明 |
| --- | --- | --- |
| 0 | 在任何映射之前返回，一个 MMIO 都不发 | — |
| 1 | 只读普查：映射 + 读引脚/时钟状态，不写 | 这一步异常 → 地址或时钟门错了 |
| **2** | 写 GCC 投票 + `applyPinConfig`（会写 GPIO 98/39 的 pad 配置）；**满足上面条件时**继续链到 SPI 初始化/环回 → SPI 引脚复用（40-43）→ 身份 → 帧读 → 发布 | **这是"最重"的档**：链一旦通，第 2 级就包含到发布为止的全部路径 |
| 3 / 4 / 5 | 与 `=2` 相同（常量存在但未被比较） | 不要指望用它们做更细的分级 |
| 6 | 额外做芯片使能：**驱动复位脚**（拉低 5 ms → 写 0xAA → 拉高） | **撞面板复位最可能在这一级**；但注意 pad 配置在**第 2 级**就已经写过 |
| 7 | 额外做主机命令 | — |
| 8 | 额外做固件上传 + 连续发布（**本板发的值**；驱动默认是 0） | 完整功能 |

**因此换板时的正确做法**（比"六级阶梯"更实在）：

1. `dby-touch=1`：只读普查。异常就停。
2. `dby-touch=2`（**必须同时发 `dby-touch-se=1`**）：一次引入"配置 + 总线 + 帧 + 发布"。若出问题，
   看**行 2 的 `s5=`**：`0`=帧读成功、`0xFFFFFFFE`=已开始未完成、其它=失败码（stage 3/4 的结果本轮不渲染，
   `gStage3Rc`/`gStage4Rc` 只被 `(void)` 引用）。`st=` 只回显请求值，恒等于你传入的数字。
3. `dby-touch=6`：只在第 2 级一切正常、且你确认复位脚不撞显示之后才用。
4. `dby-touch=8`：只在确认 IC 型号与固件兼容之后才用。

> 如果你希望"3/4/5 真的分级"，需要在驱动里把那条线程链拆开——当前它是一个整体，别再按旧文档逐级刷。
## 4. 发布契约（消费者必须一致）

```c
extern volatile int  native_touch_count;      // 活动触点数（≤10）
extern volatile int  native_touch_ids[12];    // HID id（1..255，报只留 8 位）
extern volatile int  native_touch_xs[12];     // 0..30480
extern volatile int  native_touch_ys[12];     // 0..20319（Y 自底向上）
extern volatile unsigned native_touch_seq;    // 发布序号，消费者据此去重
```

坐标换算（**不要改**）：

```
xs = px * 30480 / 1600
ys = 20319 - (py * 20320 / 2560)     // 数字面板 Y 原点在底边
```

## 5. 诊断行（读日志时按这个查）

| 行 | 内容 | 怎么读 |
| --- | --- | --- |
| 42 | `TX c=<触点数> x,y w= n= hid=<帧>/1` | `c=` 触点数、`n=` 分量节点数；`hid=<帧>` 是发布次数，应随时间增长 |
| 47 | `TOUCH st=… rcg=… rok=… se=…` | 阶段/时钟/SE 状态；`rok=1` 表示时钟就绪 |
| 48 | `TOUCH HID started=… touch-reports=… res=…` | `res=0` 表示消费者接受；`touch-reports` 应随操作增长 |
| `[touch multi]` | `reports= max= lifts=` | `max` 是历史最大同时接触数 |

## 6. 验收（缺一项都不算完）

| # | 项 | 判据 |
| --- | --- | --- |
| 1 | 单指点按 | 落点正确（四角 + 中心） |
| 2 | 快速滑动 | `c=` **始终为 1**（出现 2-4 说明"单指被拆成多指"的缺陷回来了） |
| 3 | 两指 | `TX c=2`，两点都跟手 |
| 4 | 手掌整只 | `max` 明显 >2（当前无掌拒，这是预期行为） |
| 5 | 抬起 | 手指离开 ~4 帧后消失（约 160 ms） |
| 6 | 长跑 | 连续操作 10 分钟不重启 |
| 7 | 精度网格 | `precision-grid.py`：抖动 ≤5 px、残差 RMS ≤12 px、25/25 |
| 8 | 休眠/唤醒（若有） | 唤醒后仍能采样 |

## 7. 常见故障对照

| 症状 | 最可能原因 | 怎么确认 |
| --- | --- | --- |
| 行 42 不出现 | `dby-touch` 为 0，或阶段未到达 | 看行 47 的 `st=` |
| `hid=<帧>` 不涨 | 发布循环没跑（阶段 <5） | 提高 `dby-touch` |
| `res≠0` | 消费者拒绝了发布（轴向/范围不符） | 对照第 4 节的换算 |
| 坐标正确但方向反 | Y 镜像或 X 方向 | 只改换算，不动判据 |
| 有坐标但 UI 不响应 | `sheng-touch-hid` 未开，或 HID 消费者未接 | 看行 48 `drv=` |
| 每帧都出一个新 id | 匹配逻辑被改坏 | 回退到本包的 `pairs[]` 全局分配 |
| 一按就花屏 | 第 6 级撞到面板相关引脚 | 把复位脚改 1023 复测 |

## 8. 你不需要的东西

- 不需要 GPU：本驱动的显示路径与 GPU 无关；
- 不需要 Data 卷：触摸在 `load_init_program()` 之前就可用；
- 不需要 `sheng-log=1`（它会写 userdata，见第 2 节）。

---

## 9. 出问题时的最小复现包

1. `dby-touch` 当前级别的日志窗口（8192 块，不是 80 块）；
2. 你改过的 `DbyTouchBoard.h` 差异；
3. 你的 kernel 命令行全文（**不要**只发触摸那 4 条）；
4. 一张屏幕照片（判断是 S1-S11 哪一类，见 `DBY-W09-触摸包-检测与修复指南`）。
