## 1. 一句话现状

**单指与多点都已在本机硬件上跑通**：24.4 Hz 稳定采样、SPI 零读失败、HID 消费者正常接收，
两指按下会发布两个独立触点（`TX c=2`），整只手掌会按接触面积拆成最多 10 个触点（协议上限）。
当前源码版本 `dby-touch/2026-11-03b`。

还没做的三件事：**精度网格实测（A4）**、**掌拒**、**长跑稳定性归因（A5）**。

## 3. 实现结构（四层）

```
DbyTouchProtocol.h/.c   ← 协议：native_touch_* 共享变量、行 42/47/48 的格式常量
DbyTouchBoard.h         ← 板级常量：寄存器基址、GPIO、矩阵尺寸、面板尺寸、阶段阶梯
DbyTouch.cpp (4298 行)  ← 驱动本体：映射 → 时钟/引脚 → 身份 → 帧 → 发布
DbyTouchFw.h            ← 0x30000 字节固件 blob（从 vendor 分区提取）
```

### 3.1 阶段阶梯（**以代码为准**，2026-11-04 审查更正）

驱动定义了九个阶段常量，只比较四个阈值：`0`、`≥2`、`≥6`、`≥7`、`≥8`。
`dby-touch=3/4/5` 与 `=2` **行为完全相同**——`stage2Thread` 会依次链到 `stage3Thread`（SPI 初始化/环回）、
`stage4Thread`（SPI 引脚复用 + 身份）、`stage5Thread`（8208 字节帧读 + 发布）。

| `dby-touch=` | 实际行为 | 出问题说明 |
| --- | --- | --- |
| 0 | 任何映射之前返回，一个 MMIO 都不发 | — |
| 1 | 只读普查：映射 + 读引脚/时钟，**不写** | 异常 → 地址或时钟门错了 |
| **2** | GCC 投票 + `applyPinConfig`（写 GPIO 98/39 pad）；**仅当 `dby-touch-se=1`** 才继续链到 SPI 初始化/环回 → 引脚复用（40-43）→ 身份 → 帧 → 发布 | 链有三道条件（`DbyTouch.cpp:3894-3897, 3938, 1845`）；`st=` 只回显请求值，子阶段看行 2 的 `s5=` |
| 3 / 4 / 5 | 与 2 相同（常量存在但未被比较） | 不能用来做更细的分级 |
| 6 | 额外芯片使能：**驱动复位脚**（低 5 ms → 0xAA → 高） | 撞面板复位最可能在这一级；但 pad 配置在 **2** 级就已写过 |
| 7 | 额外主机命令 | — |
| 8 | 额外固件上传 + 连续发布（默认） | 完整功能 |

> 换板时：`1` 验地址/时钟 → `2` 一次引入"配置+总线+帧+发布"（用行 47 的 `st=` 判断停在哪个子阶段）
> → 确认复位脚不撞显示后才用 `6` → 确认 IC 与固件兼容后才用 `8`。
### 3.2 多点读取器（`-03b`，本轮的核心改动）

旧版每帧只保留**最重的一个** 4 连通分量，所以捏合、三指手势在数据模型上就不存在。现版本：

1. **参考基线**：每节点只向下跟随（不变）；
2. **差分门槛**：`DBY_TOUCH_TOUCH_FLOOR = 700`（存未截断值，不变）；
3. **分量枚举**：枚举**全部** 4 连通分量，按权重保留最重 24 个；
4. **单分量判据**（一个条件都没改）：节点数 2..80、峰值 ≥ `DBY_TOUCH_TOUCH_PEAK=1200`、
   权重 = `clamp(delta, 8000) − max(30% × min(peak, 8000), 700)`；
5. **全局最小距离配对**：所有 (接触, 分量, 距离) 三元组排序后贪心分配；
   新 id 只在"没有空闲接触"时分配，且**零速度**；
6. **抬起去抖**：每个接触独立 3 帧（第 4 帧空才抬），与旧单点延迟一致；
7. **发布**：逐接触填 `xs/ys/ids`，`count` = 活动触点数（≤10）。

行 42 的格式因此变为：

```
TX c=<触点数> <x>,<y> w=<权重> n=<节点数> hid=<帧数>/1
```

`c=` 是触点数、`n=` 是分量节点数——**不要混读**。

### 3.3 审查历史（四轮，每轮都抓出真缺陷）

| 轮 | 缺陷 | 修法 |
| --- | --- | --- |
| 2 | 固定 220 px 延续半径把快滑拆成 2-4 个手指 | 预测位置匹配（上帧位置 + 逐帧速度） |
| 2 | 活动集清空时行 42 会打 `TX c=0` 配旧坐标 | 清空即清点；行 42 另加 `liveCount != 0` 门 |
| 3 | 新 id 继承了被回收槽位的**陈旧速度** → 两指静止被报成 2,4,6,8 | 新 id 显式 `vx=vy=0` |
| 3 | 按候选配接触 → 更重的新手指抢走旧 id | 改成接触优先 |
| 4 | 逐接触贪心 → 正在老化的接触抢走旁边手指的分量 | **全局最小距离分配** |

**已知无害但需知情**：两指以 ≥200 px/帧 相互穿过时 id 仍会互换一次（位置正确，消费者只用 id 判抬起）；
"同一帧内抬起 + 新按下"会把 id 转给新手指（与旧单点一致）。

## 5. 已知限制（诚实清单）

| # | 限制 | 影响 | 候选修法 |
| --- | --- | --- | --- |
| 1 | **没有掌拒** | 手搭在屏幕上 → 最多 10 个"手指"，UI 可能缩放/抖动 | 节点数阈值（>60 判手掌）/ 总面积比例 / `[touch multi]` 软限流 |
| 2 | 无压力/接触面积上报 | 绘图类应用缺一个维度 | 可从权重推导，需先定标 |
| 3 | 无手掌边缘抑制 | 握持时边缘误触 | 与 1 合并处理 |
| 4 | 快速交叉时 id 互换一次 | 无害（消费者只用 id 判抬起） | 可加"上一帧速度连续性"加权 |
| 5 | 精度网格未实测 | 不知道非线性程度 | 用 `work/verify/precision-grid.py`（打点计划已备） |
| 6 | 长跑稳定性未归因 | 未知长时间使用的漂移/漂移 | 参考基线只向下跟随，理论上会自愈；需实测 |
